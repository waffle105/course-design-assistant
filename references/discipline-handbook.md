# 教研组纪律与机制操作手册

> 本文件是教务长和教研组员的操作底线，每阶段启动前必须过一遍自检表。

## 7条核心纪律

### ① 流程纪律（接力式，不可跳跃）

**允许**：
- 阶段N验收通过 → 进入阶段N+1
- 阶段6内3路并行（课件/案例/习题）
- 阶段8独立于1-7，可独立启动

**禁止**：
- 阶段N未通过 → 强行进入阶段N+1
- 跳过结构搭建直接做课件
- 跨阶段调用未验收的产出

**三道关验收**（每阶段必经）：
1. 组员自查（对照验收标准逐项✓）
2. 教务长验收（对照标准+质量判断）
3. 用户验收（满意度确认）

### ② 信息纪律（任务书唯一权威）

**任务书修订权**：仅教务长。组员发现需修订时，向教务长提议，教务长评估后决定。

**组员输入**：只接收"任务书 + 上游产出"。产出必须标注"基于任务书X + 上游产出Y"。

**禁止**：
- 组员直接接收用户口头指令
- 跨阶段信息不一致时擅自改动
- 组员擅自修订任务书

### ③ 验收纪律（标准公示，打回有理）

**打回双轨计数**：

| 轨道 | 上限 | 升级动作 |
|---|---|---|
| 教务长打回 | 3次 | 第3次未过 → 用户决策（A调标准/B换组员/C拆分/D暂停）|
| 用户打回 | 3次 | 第3次未过 → 教务长仲裁（需求对齐→任务书修订或攻坚组员）|

两类独立计数，互不消耗。超过任一上限，任务冻结。

**打回必附**：不符合的具体标准编号 + 修改建议。禁止只说"不合格"。

### ④ 协作纪律（单线沟通）

**允许**：
- 通过教务长协调
- 跨阶段信息冲突由教务长决策
- 阶段6并行3路通过教务长互看上游（知识地图+教学活动SOP）

**禁止**：
- 组员之间直接沟通
- 用户绕过教务长直接下指令
- 并行组员直接互发指令

### ⑤ 交付纪律（完整版本，全程可追溯 + 产出不缩水 + 物化为成品文件）

**5a 版本与追溯**
- 版本号：v1.0 → v1.1（小修）→ v2.0（大改）
- 变更记录：原因+人+时间
- 禁止不带版本号、不记录变更、覆盖前序版本

**5b 产出完整性纪律（禁压缩/禁摘要/禁截断）**
- 每阶段产出**必须完整原文**传递给下游，禁止摘要、缩写、"总结一下"、只传结论。
- 产出过长时按知识点/单元分块传递，但每块必须完整，拼起来=全文。
- 教务长转交前自检：交付内容长度 ≥ 模板字段要求的最低长度，字段无缺失。
- 禁止用"详见上游""同上""略"等省略语代替实际内容。
- **违反 = 验收不通过，打回重做**（计入打回计数）。

**5c 交付物物化纪律（成品文件，禁止以 md 顶替）**
- 阶段 6/7 的 7 类交付物，**除课程说明书（md）外必须物化为真实 .docx / .pptx / .pdf 文件**，放在工作目录的 `产出物/` 子目录。
- **物化方法**：
  - `.docx`：用 `python-docx` 生成（讲师手册/学员手册/习题集/备课地图/案例集/教具卡片）
  - `.pptx`：用 `python-pptx` 生成（课件）
  - `.pdf`：由 `.docx` 经 LibreOffice 命令行转出，或用 `reportlab`/`fpdf` 直生
- **禁止**①把填好的 md 模板当交付物；②只说"已生成"却不真出文件；③在对话里用代码块展示内容冒充"已交付"。
- 阶段 7 最终打包：物料包结构（`01_课程说明书.md`/`02_课件.pptx`/...）必须对应**真实物理文件存在**；文末用 `present_files` 一次性交付所有文件给用户。
- **违反 = 阶段 7 验收不通过**。

**PPT 制作（课件制作师必读）**：用 `python-pptx` 按 PPT 结构模板（开头 1-2 页 + 正文每单元 N 页 + 结尾 2-3 页）生成 .pptx。保证有可用文件，用户可在 PowerPoint 里二次美化。

### ⑥ 时效纪律（阶段封顶）

| 阶段 | 标准时长 |
|---|---|
| 1 选题诊断 | 30min |
| 2 目标设计 | 45min |
| 3 结构搭建 | 60min |
| 4 内容填充 | 120min |
| 5 教学活动 | 90min |
| 6 课件打包 | 120min（3路并行取最长）|
| 7 评审迭代 | 60min |
| 8 培训项目（可选）| 120min |

用户反馈需24h内回复。紧急情况可越级。

### ⑦ 变更纪律（闭环管理）

**变更分级**：
- **任务书级**：影响交付物配置/课时/学员画像 → 教务长修订任务书 → 通知所有相关组员
- **阶段内**：不影响任务书 → 组员自查修改 → 报教务长备案

**禁止**：用户直接给组员下修改指令；跨阶段变更不通知上游。

## 5项机制

### 机制1：超时机制

```
触发：阶段产出超过标准时长
  ↓
① 自动诊断超时原因
   · 信息不全 → 追加主动发问
   · 工具未就绪 → 补充工具说明
   · 计算超时 → 拆分任务
  ↓
② 自动安排补救
  ↓
③ 用户透明化（同步显示原因+补救措施）
  ↓
④ 严防"假完成"：超时未完成 = 未完成 = 不准进下一阶段
  ↓
⑤ 记录入变更记录；累计超时存档
```

**延展规则**：超时后仍未完成，教务长可手动延长一次（+50%标准时长）。第二次超时 → 强制升级用户决策。

### 机制2：打回上限机制

见纪律③。仲裁会议流程：

```
用户打回第3次
  ↓
教务长整理3次打回完整记录
  ↓
与用户进行"需求对齐会议"
  ↓
需求变更？ ─ 是 → 升级任务书修订 → 重新走流程
          └ 否 → 教务长指定"攻坚组员"专项处理
  ↓
仲裁期间任务冻结
```

### 机制3：可省略机制

```
组员识别可省略项
  ↓
向教务长提议（⚠️提议省略 + 原因）
  ↓
教务长评估：合理 → 修订任务书（标⚠️省略确认）
           不合理 → 驳回，组员继续执行
  ↓
教务长将修订后任务书提交用户确认
  ↓
用户确认 → 从交付清单移除
用户否决 → 组员继续执行
  ↓
变更记入任务书 changelog
```

**可省略识别标准**：
- 用户明确不需要
- 课程规模不需要（2小时内课可省案例集）
- 重复或冗余

### 机制4：时效自动化

```python
# 伪代码：阶段启动时
automation_update(
    mode="create",
    name=f"教学开发阶段{N}-{阶段名}",
    scheduleType="once",
    scheduledAt=<现在 + 标准时长>,
    prompt=f"检查课程开发阶段{N}是否完成。如未完成，启动超时机制：诊断原因+安排补救+通知用户。",
    cwds="<当前工作目录>"
)

# 阶段完成时
automation_update(mode="delete", id=<上面创建的automation id>)
```

**全部用 once，不用 recurring**。完成后立即 delete。

### 机制5：纪律自检表

每阶段启动前，教务长逐项确认：

```
□ 流程：上一阶段验收通过了吗？
□ 任务书：每项任务的依据清晰吗？
□ 验收标准：标准事先公示了吗？
□ 沟通路径：所有变更通过教务长吗？
□ 版本管理：每个产出都有版本号吗？
□ 时效：阶段内时长是否在标准内？
□ 变更：所有变更都有记录吗？
□ 超时：超时是否说明原因+自动补救？
□ 打回：总管3次/用户3次是否在限内？
□ 省略：可省略项是否经教务长→用户确认？
□ 任务书修订：只有教务长修订了吗？
□ 阶段6并行：3路是否同步推进？
□ 产出完整性：上游产出是否完整原文传递，无摘要/截断/省略语？
□ 交付物物化：除课程说明书外，6类交付物是否已物化为 .docx/.pptx 真实文件？
```

全✓ 才推进。任一项✗ → 先处理后推进。
